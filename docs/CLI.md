# GRASS Local CLI

## Purpose

The local CLI is a thin client of the transport-neutral Application and Query
APIs. It does not commit Events, mutate projections, or access a write-capable
EventStore. Commands that change a run use `LocalSimulationApplication` and
`OpenedRun`; inspection uses `LocalSimulationQueries`.

The package installs `grass` and also supports `python -m grass.cli`.

## Data root

The default data root is `.grass` under the current working directory:

```text
.grass/
    grass.db
    world_snapshots/
```

Use `--data-dir PATH` before the command family to replace the entire root:

```text
grass --data-dir ./experiment run list
```

The CLI has no global/XDG configuration and stores no credentials.
Template list/show/init do not use the data root. They read trusted packaged resources or
write only the explicitly selected authoring destination.

## Commands

```text
grass template list
grass template show NAME
grass template init NAME DESTINATION

grass world validate WORLD

grass run create WORLD
grass run list
grass run status RUN [--branch BRANCH]
grass run step RUN [--branch BRANCH] [--target-time-ns N]
grass run advance RUN [--branch BRANCH] [--target-time-ns N] [--max-steps N]
grass run verify RUN

grass branch list RUN
grass branch create RUN --from PARENT --branch-id CHILD

grass inspect state RUN [--branch BRANCH]
grass inspect events RUN [--branch BRANCH] [--scope visible|origin]
grass inspect branches RUN
grass inspect jobs RUN [--branch BRANCH]
grass inspect job RUN JOB [--branch BRANCH]
grass inspect decisions RUN [--branch BRANCH]
grass inspect decision RUN DECISION [--branch BRANCH]
grass inspect actors RUN [--branch BRANCH]
grass inspect actor RUN ACTOR [--branch BRANCH]
grass inspect actor-observations RUN ACTOR [--branch BRANCH]
grass inspect actor-decisions RUN ACTOR [--branch BRANCH]
grass inspect actor-plans RUN ACTOR [--branch BRANCH]
grass inspect actor-jobs RUN ACTOR [--branch BRANCH]
grass inspect actor-history RUN ACTOR [--branch BRANCH]
grass inspect config RUN
grass inspect providers RUN
```

RunIds are lowercase hyphenated UUIDs generated by the Application layer.
There are no run names or aliases. An omitted branch means the persisted root.
For `run step` and `run advance`, explicitly naming that root has the same
open and recovery behavior as omitting `--branch`.
`run advance` stops with the exact runtime stop reason and has no
`--until-idle` mode.

## Typical workflow

```text
grass world validate ./my-world
grass run create ./my-world
# Retain the reported UUID as RUN.
grass run status RUN
grass run advance RUN
grass inspect state RUN
grass inspect events RUN
grass branch create RUN --from root --branch-id alternative
grass run advance RUN --branch alternative
grass run verify RUN
```

The editable world directory is not needed after creation. Every
package-backed run reopens from its immutable per-run snapshot.

## Lifecycle behavior

Registration and genesis cannot be one transaction across all storage
boundaries. A valid registered run with an empty parentless root is therefore
reported by `run list` as `RECOVERABLE`.

`run status` is read-only and reports `RUN_RECOVERY_REQUIRED` for this state.
It never initializes history. `run step` and `run advance` open the run and may
perform the existing idempotent genesis recovery. A nonempty malformed root is
invalid and is never replaced or repaired by the CLI.

Catalog health values are CLI presentation only:

- `OK`: material, topology, genesis, replay, and all branches verify;
- `RECOVERABLE`: valid material with an empty canonical root;
- `INVALID`: material or canonical history cannot be verified.

One invalid run does not hide other catalog entries.

## Branches and Events

Branch creation captures the parent's exact current `HistoryPosition` once and
creates the child at that committed-transition boundary. Later parent progress
does not move the fork.

Visible Event scope includes inherited ancestry. Origin scope includes only
transitions committed on the viewed branch. Event output always retains whole
atomic transitions; Event sequence is ordering, not inferred causality.

## JSON v1

Place `--json` before the command family:

```text
grass --json run list
```

Success and failure envelopes are:

```json
{"schema_version":1,"command":"run.status","data":{}}
```

```json
{"schema_version":1,"command":"run.status","error":{"code":"RUN_NOT_FOUND","message":"..."}}
```

In JSON mode stdout contains exactly one JSON document. Prompts and warnings
use stderr. Identifiers are strings, logical times are integer nanoseconds, and
operational timestamps are UTC `YYYY-MM-DDTHH:MM:SS` values without a suffix.
Object keys and unordered domain collections have deterministic ordering.

Positions distinguish the branch being viewed from the branch on which the
exact transition originated:

```json
{
  "run_id": "...",
  "viewed_branch_id": "alternative",
  "transition_ref": {
    "origin_branch_id": "root",
    "transition_id": "..."
  },
  "logical_time_ns": 0
}
```

Event JSON includes payload, provenance, causation references, and correlation
identity. `inspect config` and `inspect providers` include only persisted,
non-secret configuration.

## Exit codes

- `0`: a valid command result, including all normal runtime stop reasons;
- `1`: a handled world, run, execution, integrity, snapshot, or storage error;
- `2`: command-line usage error;
- `130`: interruption.

Stable JSON error codes are:

```text
USAGE_ERROR
TEMPLATE_NOT_FOUND
TEMPLATE_INVALID
```

## Human decisions

`CliHumanDecisionSource` implements the existing transport-neutral human
decision boundary. It displays an actor-relative request on stderr and accepts
one strict JSON decision on stdin. Plan drafts use local step keys; trusted CLI
code allocates Plan and PlanStep identities.

The production Slice-16 composer remains occurrence-only, so ordinary authored
WorldPackages cannot yet configure terminal actor loops. The source is tested
through an injected trusted actor-capable composer and the normal
`HumanDecisionInvoker`, validation, provenance, and engine commit path.

## Templates

`template list` and `template show` expose deterministic trusted registry metadata.
`template init` copies one fixed trusted file inventory into a new ordinary editable
WorldPackage directory. The destination must not exist, is never merged or overwritten,
and its basename becomes the copied `world_definition_id` before normal package and
production-composer validation.

The Slice-17 starter is `occurrence-counter`. It changes one world StateVariable through
one referenced GEL occurrence and uses no actor semantics or special runtime path.

## Deliberately deferred

- run aliases and authored run-configuration files;
- provider profiles, credentials, probes, and client-managed submission;
- actor bootstrap and actor-capable ordinary WorldPackages;
- actor-capable templates and examples from Slice 18 or later;
- historical-position selectors, pagination, and filtering;
- branch rename, delete, merge, and rebase;
- Diagnostics/Debug APIs, TUI, colors, and shell completion;
- HTTP, WebSocket, backend, and frontend interfaces.
